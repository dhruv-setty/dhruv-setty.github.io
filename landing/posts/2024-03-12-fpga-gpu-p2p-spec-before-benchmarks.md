## Context

The device side of a GPU peer-to-peer data path requires enumeration and BAR assignment, exact TLP header decode, and a copy engine whose completion handoff software can rely on. Each is a correctness property and shall be established before throughput is measured.

The IATO repository implements a Type 0 configuration space, a TLP header decoder, a descriptor ring DMA engine with a C driver, and a TLA+ model of PCIe posted-write ordering. It is not a production device, driver or IP core, and it implements neither a GPU nor a peer-to-peer transfer. All results derive from model checking, simulation and open tool synthesis, with no physical FPGA and no vendor tools. Every figure was generated by the captures workflow on an `ubuntu-24.04` runner.

## Design rationale

### Specifications

| Specification | Statement | Result |
|---|---|---|
| `spec/pcie/TLPOrdering.tla` | A producer writes data, then a flag; a consumer reads the flag, then the data | Safe with strict posted ordering. Relaxed Ordering on the flag write lets the consumer read stale data |
| DMA descriptor handoff (Sail, in `spec/sail/`) | The driver writes source, destination and length, sets OWN last, issues a write barrier, then rings the TAIL doorbell. The engine writes back OWN cleared and DONE set, and only then advances HEAD and DONE_CNT in the same cycle | Part of the 14 Sail assertions, all passing |

Relaxed Ordering shall not be set on the flag write of a flag-then-data protocol. A peer-to-peer fast path shall not apply RO without regard to this constraint.

### Configuration space

BAR0 is a 32 bit BAR; BAR2 and BAR3 form a 64 bit prefetchable pair. The low bits of each BAR are masked to the BAR size so that the all-ones write and read-back sizing protocol reports the size.

### TLP header decoder

The decoder is purely combinational and holds no state. The verification obligation reduces to field extraction from the correct bits of the 3DW or 4DW header. The attributes field shall be decoded exactly, since the ordering result depends on RO.

### DMA engine

The engine walks a ring of 32 byte descriptors in host memory, transfers 8 bytes per beat over one memory port shared between reads and writes, and holds up to `MAX_RD` reads outstanding. The driver reaps by reading DONE from memory; the fast path performs no register access. An earlier revision updated DONE_CNT one cycle after the DONE writeback, exposing a stale count to the driver. The RTL now advances HEAD and DONE_CNT in the same cycle, and the harness checks the count after every run.

### Throughput

`bench/run.sh` sweeps copy size, memory latency and `MAX_RD`. The ceiling is 4 bytes per cycle: the single port accepts one request per cycle, shared between reads and writes. Values in bytes per cycle; every copy is verified byte for byte.

| Copy size | Latency 1 | Latency 8 | Latency 32, MAX_RD 8 | Latency 32, MAX_RD 32 |
|---|---|---|---|---|
| 64 B | 2.46 | 1.88 | 0.78 | 0.78 |
| 512 B | 3.71 | 3.35 | 1.39 | 2.99 |
| 4 KiB | 3.96 | 3.71 | 1.54 | 3.79 |
| 64 KiB | 4.00 | 3.76 | 1.56 | 3.93 |

`dma_engine` with `MAX_RD` 8 places and routes at 129.10 MHz on a Lattice LFE5U-25F, out of context, which bounds the 4 bytes per cycle ceiling at about 516 MB/s.

## Observations

- At latency 32 with 8 reads in flight, throughput is bound by Little's law at 8 beats of 8 bytes per round trip. With 32 in flight it is within 2 percent of the ceiling.
- Small copies are bound by descriptor fetch and writeback (Figure 8), which motivates descriptor batching or prefetch.
- Every assigned address is naturally aligned to its size, and each 64 bit BAR2 is assigned above the 4 GiB boundary.
- Icarus emits `sorry: constant selects` warnings on `rtl/pcie/cfg_space.sv`; Verilator lints the same file clean.
- The testbenches set no `timescale`; GTKWave labels simulator time steps as seconds.

## Limitations

- The 129.10 MHz figure is an open tool estimate, not a vendor tool, ASIC or FPGA measurement. Fmax with `MAX_RD` 32 is not measured.
- Not implemented: completion ordering and a TLP generator wired to the DMA engine; descriptor prefetch, scatter gather and MSI on completion; a Linux PCI driver skeleton on the same register map; SystemVerilog assertions on the DMA handoff checked with SymbiYosys.
- Out of scope: physical FPGA measurement and the GPU side of a peer-to-peer path.
